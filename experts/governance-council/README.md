# 三省六部治理团 / Governance Council

一套跨项目复用的「三省六部」治理机制：产品起草、架构封驳、设计定稿、研发实现、测试把关、运营反馈，只把重大决策上报给人。

## 类型

Team 型（1 主理人 + 6 部协同，共 7 个角色）

## 核心机制

| 机制 | 说明 |
| --- | --- |
| 宪法驱动 | 主理人开工第一步必须先定位当前项目的 `docs/governance/CONSTITUTION.md`；找不到就停下给模板，**严禁自己编一套默认规则然后开干** |
| L0/L1/L2 分级决策 | L0 部内、L1 跨部自行消化，不打断人；**只有 L2 上报批红** |
| 封驳权 | 门下省（架构审议）可否决中书省（产品）提案 |
| 上线否决权 | 刑部（测试）独立于研发，是最后一道闸门 |
| 不绑定项目 | 所有角色运行时读当前项目的宪法，不把其他项目的经验当成本项目的 |

## 角色

| 花名 | 角色 | 掌什么 |
| --- | --- | --- |
| 莫执中 | 中枢调度官（主理人） | 拆任务、派活、跟踪阻塞、准备批红简报 |
| 许定纲 | 产品主笔（中书省） | 需求调研、起草提案、维护路线图与优先级 |
| 高维衡 | 架构审议官（门下省） | 结构影响评估、技术选型、ADR，持封驳权 |
| 容正形 | 体验设计主笔（礼部） | 交互流程、视觉规范、响应式与可访问性，持设计定稿权 |
| 寇成器 | 研发工程师（兵部兼工部） | 按提案实现、扩展点、构建部署、变更日志同步 |
| 严究底 | 质量把关人（刑部） | 缺陷复现、回归、功能验收、质量门禁，持上线否决权 |
| 闻众声 | 用户运营（吏部） | 收集反馈、对外文档、问题分类转派 |

## 使用示例

- 给当前项目加个功能，走完整流程
- 当前有哪些事在阻塞，哪些需要我拍板
- 从架构角度审一下这个方案会不会破坏结构

## 头像

头像在 `avatars/` 目录下，512×512 PNG，单张不超过 500KB。替换时保持同名同规格即可。

## 安装

将专家包目录放到专家目录下：

```
C:\Users\jwl\.workbuddy\plugins\marketplaces\my-experts\plugins\governance-council\
```

然后运行注册命令使其可见：

```bash
python3 scripts/register_expert.py <expert-dir>
```
